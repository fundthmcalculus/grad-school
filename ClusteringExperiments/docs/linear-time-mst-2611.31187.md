# Deterministic linear-time MST (arXiv:2611.31187): what it means for VAT/iVAT

Paper: S. Khanna, A. Putterman, J. Song, *A Deterministic Linear Time Algorithm
for Minimum Spanning Tree*, arXiv:2611.31187v1 [cs.DS], 23 Nov 2026 (preprint,
not peer-reviewed). Companion repo `github.com/Louiealbp/DLMST` holds the PDF
and AI-generated intermediate write-ups only — **no code**.

Implementation and benchmarks: `fundthmcalculus/clustering`
(`src/tribbleclustering/dlmst.py`, `cdlmst.pyx`, `benchmarks/mst_pareto.py`,
`benchmarks/rust_dlmst/`).

## 1. The claim

| Item | Content |
|---|---|
| Theorem 1.1 | Deterministic, comparison-based MST in **O(m)** worst case on any connected multigraph |
| How | Shows decision-tree complexity T*(m,n) = O(m); Pettie–Ramachandran (JACM 2002) then gives an O(T*) = O(m) algorithm |
| Previous best explicit | O(m α(m,n)) — Chazelle 2000 |
| Prior linear results | Randomized (Karger–Klein–Tarjan 1995); word-RAM integer weights (Fredman–Willard 1994); dense graphs m = Θ(n²) via array Prim |
| AI provenance | §1.4: "main ideas … entirely generated by AI" (OpenAI "Astra 6.2", 15-agent runs); authors verified and simplified |

### Algorithm 2 (the outer loop)

1. k Borůvka steps (k constant) — shrinks n by 2^k.
2. `Certificate(G')` → forest F (Lemma 3.1).
3. Compute U(F): edges **not** supported by F (supported = endpoints joined
   by F restricted to weight ≤ w(e); cycle property ⇒ discardable).
   Komlós path-max: O(m) comparisons.
4. Recurse on F ∪ U(F). Lemma 3.1 bounds |F| + |U(F)| + Σ|E_i| ≤ εm + C_ε√(nm),
   so with the Borůvka shrink, total recursive size ≤ m/2 ⇒ T(m) = T(m/2) + O(m).

### The certificate (§3) — why it cannot be run

* Portals, spokes, projection of edges onto portal graphs, t² rounds in t
  blocks with t = γ·d³ at recursion depth d, r = 8t³.
* Each edge is assigned to one round by a **schedule**. Existence of a good
  schedule is shown by a counting/probabilistic argument over *histories*
  (Def. 1.5), bounded via Fredman's maximizing-pattern count e^{O(√NM)}.
* Making it deterministic: "we can **enumerate all possible schedules and
  check all possible histories** to find a good schedule. Although this may
  incur enormous computational overhead, it requires no comparisons" (§3.4).
  The same enumerate-and-check is used to find the universal query set S* for
  estimating preferred actions (§3.5).
* Running time then comes from Pettie–Ramachandran, which itself
  brute-forces optimal decision trees for log log log n–size sub-instances.

**Verdict:** a comparison-complexity result. The certificate procedure is
not implementable at any useful size; the "linear-time algorithm" exists as
the PR02 reduction, whose constants are galactic. There is no reference
implementation, and none is plausible.

## 2. Relevance to VAT/iVAT

| Fact | Consequence |
|---|---|
| VAT runs on the **complete** graph: m = n(n−1)/2 | Array-Prim is already O(n²) = O(m) — **linear**. The paper says so itself (§1.1). Zero asymptotic gain is available. |
| VAT needs Prim's **visit order**, not just the MST | Any MST suffices: with distinct weights, Prim restricted to the MST from the same seed reproduces the order exactly (cut property) in O(n log n). Already exploited by the `boruvka_vat.py` spike. |
| iVAT = minimax (path-max) distances on the MST | iVAT can be built from the MST alone — no VAT matrix — by a Kruskal-reconstruction-tree (KRT) running max, row-parallel. |
| Prim's round loop is serial; Algorithm 2's passes are row-independent | The real lever is **parallelism and memory**, not asymptotics. |

## 3. What was built: the runnable skeleton of Algorithm 2

Practical deterministic certificate with the same contract (forest F + the
edges it does not support):

| Step | Paper | Implementation | Cost on K_n |
|---|---|---|---|
| Borůvka | k steps | subsumed: the 1st of the k lightest edges per vertex *is* one Borůvka step | — |
| Certificate | §3 portals/schedule | F₀ = MSF(k lightest edges per vertex), then one **contraction pass** (lightest edge between every pair of F₀-components, c ≤ 256; Borůvka merges beyond) → spanning F | 1 full + ½ pass |
| U(F) | Komlós path-max | KRT leaf order: F-minimax(i, j) = max(g[i..j−1]) ⇒ each row is one running max; **exactly one comparison per pair** | ½ pass |
| Recurse | on F ∪ U(F) | U(F) is tiny (0–5 edges of ~10⁷ in tests) ⇒ Kruskal | O(n log n) |
| VAT order | — | Prim on the MST (heap) | O(n log n) |
| iVAT | — | KRT running max per row, row-parallel | n² writes |

Correctness: p, q and the iVAT image are **bit-identical** to the existing
Prim/iVAT kernels on every test (f32/f64, matrix/points, 2 ≤ n ≤ 10 000,
≥600-cluster inputs that force the Borůvka fallback). With weight ties the
tree is a valid MST but may differ from Prim's tie choice.

Implementations: numpy reference → Cython/OpenMP (`floating` fused type) →
Rust (std threads, C ABI, ctypes).

## 4. Results

These runs used 4 CPUs, 15 GB of RAM, d=10 and 8 Gaussian blobs. Times are
end to end from points, and peak RSS was measured in a fresh subprocess per
point. Full tables and Pareto plots are in `clustering/benchmarks/README.md`,
with the raw data in `benchmarks/baselines/mst_pareto_vm.json`.

| Task (f64) | Existing best | Cert+filter (C) | Δ |
|---|---|---|---|
| VAT order, n=24k, from points | Prim on matrix 3.97 s / 4.61 GB; Prim from points 5.03 s / 2 MB | **1.50 s / 6 MB** | 2.6× faster than Prim on the matrix at ~770× less memory; 3.4× faster than Prim from points |
| iVAT image, n=16k | in-place iVAT 4.05 s / 2.05 GB (input destroyed) | **1.19 s / 2.05 GB** (input kept) | 3.4× faster, same memory |
| MST stage given D, n=24k | Prim 1.45 s | **0.66 s** (4 threads); 2.15 s (1 thread) | the win is all parallelism |

Language comparison, using the same algorithm and passes:

| Path | Cython | Rust (std threads) |
|---|---|---|
| MST stage on the matrix, n=24k f64 / f32 | 663 / 516 ms | 756 / 492 ms |
| VAT order from points, n=24k f64 | 1.50 s | 2.12 s |
| Serial dense Prim, n=24k f64 | 1448 ms | 2111 ms |

The paths bound by memory bandwidth are equal. On the compute-bound ones
Rust is 1.4–1.5× slower, because Cython is built with `-ffast-math`, which
lets GCC vectorize the floating-point reductions, and stable Rust cannot opt
into that.

## 5. Takeaways for the thesis

1. The paper settles a 70-year theory question but changes **nothing
   asymptotically** for VAT/iVAT: dense Prim was already linear in m.
2. Its *structure* — sample a certificate, filter by the cycle property,
   recurse on a tiny remainder — is what pays off on dense dissimilarity
   data: three row-parallel passes replace Prim's n serial rounds, and the
   filter needs no matrix, so VAT order and iVAT run **from points** with
   O(n) working memory (iVAT: only its own output).
3. This supersedes the earlier conclusion in `DC_VAT_FINDINGS.md` that exact
   parallel VAT needs parallel Borůvka (O(n² log n) work): certificate+filter
   is O(n²) work, ~3 passes, independent of the number of clusters up to the
   256-component contraction cap.
4. Language: Rust and Cython are equal on the paths bound by memory
   bandwidth. Rust is 1.4–1.5× slower on the compute-bound kernels because it
   has no fast-math. Rust adds no Pareto point.
5. Open: the 4-core box understates the parallel gain, so re-run
   `mst_pareto` on the 32-core reference machine. The single-thread
   crossover is ~1.5×, so the gain should grow roughly with core count until
   memory bandwidth saturates.
