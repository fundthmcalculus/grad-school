# Converting a Consequent-First Fuzzy Inference System into a ReLU Network

**A five-part study of whether the Bede–Kreinovich–Toth equivalence can warm-start
gradient descent.**

Draft against live code. Every number is generated by a script in this directory
and lands in [`outputs/`](outputs/); nothing here is transcribed by hand. The
per-part laboratory record, including the hypotheses as they were written *before*
each run, is [`RESULTS.md`](RESULTS.md).

---

## Abstract

Bede, Kreinovich & Toth prove that Takagi–Sugeno fuzzy systems and ReLU networks
compute the same class of functions, and give the map between them. Their
direction is network → rules, for explainability. We run it backwards: TRIBBLE
constructs a fuzzy inference system consequent-first, without gradient descent,
in a fraction of a second — if that FIS converts to a network, the network
inherits its structure as initial weights.

**The conversion works.** In one dimension it is an identity, verified at machine
precision against the package's own Ruspini partition builder. In *n* dimensions
the tetrahedral construction is exact and compact — `O(n)` ReLU units per rule at
`O(log n)` depth, with only `n+1` rules active anywhere — and on real problems the
converted network reliably starts *at or above the accuracy of the FIS it came
from*, having seen no labels.

**The warm start pays only in one regime, and not the one we expected.** Dataset
size is irrelevant: PhiUSIIL at 235,795 rows reaches its target in 25 minibatch
updates, so a 2-second FIS fit can never repay itself. What matters is
*updates-to-target*. On a damped double-pendulum operator needing 5,410 updates,
the warm start reaches R² 0.9 in 2.45 s against 11.62 s — 4.7× on wall clock,
15.6× in updates.

**But a trivial baseline beats it almost everywhere.** The same axis-aligned ReLU
knot layer with knots at per-feature *quantiles* and one closed-form ridge solve
matches or beats the FIS-derived initialization on every problem above one
dimension. Across five independent lines of evidence the conclusion is the same:
**the architecture the equivalence points at is the contribution; the FIS's knot
placement is not.**

A controlled A/B isolates why. The same FIS, conversion, and data generator, with
fluid damping as the only difference: damped, the conversion is essentially exact
(R² 0.8747 against the FIS's 0.8746); undamped, it loses 0.11 R² outright. **The
axis-aligned conversion is exact exactly when the FIS is additive.**

## 1. The equivalence, and which direction we run it

The identity is small and exact. A triangular membership function with feet `a`,
`c` and apex `b` is a sum of three ReLUs — quoted from the 2023 paper:

```
A(x) = [phi(x-a) - phi(x-b)] / (b-a)  -  [phi(x-b) - phi(x-c)] / (c-b)
```

which expands to `s_a·relu(x-a) − (s_a+s_c)·relu(x-b) + s_c·relu(x-c)`. A fuzzy
term *is* a hidden-layer motif; its knots *are* the ReLU biases.
`fis2nn.triangle_to_relu` implements exactly this, including the *shoulder*
forms (`a = -inf`, `c = +inf`) that a Ruspini partition's end terms need. It
rejects genuinely *degenerate* terms — a vertical side, `a == b` or `b == c` —
because those are discontinuous and no finite sum of ReLUs is; see §7a.1 for
what it used to do with them instead.

The 2025 sequel lifts this past one dimension by replacing triangles with
**tetrahedral** membership functions, giving one TSK rule per triangulation
vertex: `If M_p(x) then z = f(p)`.

**The asymmetry that governs everything below:** their triangulation is induced by
the linear regions of the network being decompiled, so their interpolation is
exact by construction. A TRIBBLE FIS is *not* piecewise linear — Gaussian
memberships, a product t-norm, a normalization step — so running the map backwards
has no canonical triangulation. We impose one, and the error that introduces is
what this study spends most of its time measuring.

## 2. What is exact, and verified

Thirty tests across two suites, all passing, all checked at machine precision
rather than a tolerance chosen to pass.

| claim | verification |
|---|---|
| triangle = 3 ReLUs, trapezoid = 4 | `< 1e-12` over a 24,001-point grid, both shoulder forms |
| degenerate terms raise rather than lie | both orientations, triangle and trapezoid; `fis_knots` skips and warns (§7a.1) |
| recorded seconds exclude evaluation | a wide net on a large eval set stays under 50 ms for 3 epochs |
| 1-D Ruspini TSK = 1-hidden-layer ReLU net | `< 1e-10`, **one hidden unit per apex knot**, no data touched, 25 random partitions |
| PWL decomposition exact *between* knots | midpoint check — separates an identity from an interpolation that merely hits the samples |
| Freudenthal hat closed form | **zero** error vs Kuhn interpolation at n = 1, 2, 3, 5, 8 |
| barycentric partition of unity | `1e-15` at n = 32, and only `n+1` terms nonzero |

The n-dimensional hat has a closed form that is a small ReLU circuit:

```
phi_v(x) = relu( 1 - relu(max_i d_i) - relu(max_i (-d_i)) ),   d = (x - v)/h
```

Since `max(a,b) = a + relu(b−a)`, that is `2(n−1)+3` units at depth
`⌈log₂ n⌉+2` — **O(n) units, O(log n) depth**, the n-dimensional analogue of
"a triangle is three ReLUs".

## 3. Scalability is real, and is not the binding constraint

A dense tetrahedral partition has `(K+1)ⁿ` rules — the explosion
`tribblefis.anfis` raises `RuleExplosionError` over. Nothing here enumerates it:
`n+1` rules fire at any point, found by sorting fractional coordinates, and only
vertices the data reaches are ever built.

| dataset | features | dense partition at K=8 | rules built |
|---|---|---|---|
| Concrete | 8 | 43,000,000 | 5,162 |
| WEC | 12 | 282,000,000,000 | 1,788 |

**The wall is statistical instead.** Concrete at K=8 has 0.16 rows per vertex —
six times more rules than training rows — and refining cannot help, because the
occupied-vertex count saturates near `N(n+1)` while resolution keeps climbing. You
cannot buy resolution and support at the same time in high dimension.

The usable form is a hybrid: additive main effects, where all `N` rows feed every
1-D profile, plus a tetrahedral correction on the top few features at a resolution
chosen to keep ~10 rows behind every vertex. It improves the conversion 17–30% on
every dataset. Aligning the lattice to the FIS's own knots (`AxisWarp`) does not
lower the best fidelity but makes it robust: the bounding-box lattice collapses
when asked for a subspace it cannot support (0.597 at k=4 on Concrete) where the
warped one holds flat at 0.255–0.265.

## 4. The warm start: one regime, and how to recognize it

Four datasets in Parts 1–3 all said the same thing — the hot start loses on wall
clock — and PhiUSIIL was chosen to settle whether *scale* was the missing
ingredient. It is not:

| | rows | updates to target | FIS fit |
|---|---|---|---|
| PhiUSIIL | 235,795 | **25** | 2.0 s |
| damped pendulum | 43,400 | **5,410** | 0.84 s |

**Row count buys per-epoch cost; it does not buy epochs-to-target, and
epochs-to-target is what a warm start saves.** Ranking candidate problems by
minibatch updates to reach R² 0.9 (`outputs/slow_problems.md`) put an
ill-conditioned linear problem at 36 updates — Adam's per-parameter scaling
absorbs a condition number of 10⁴ — and the damped pendulum operator at 3,444.

On that problem the hypothesis is confirmed for the only time in the study:

| arm | R² at start | to R² 0.9 | updates |
|---|---|---|---|
| `hot` | **0.8747** | **2.45 s** | **347** |
| `he` | −2.1208 | 11.62 s | 5,410 |

At R² 0.93 only the hot arms arrive at all.

## 5. The result that survives all five parts

`quantile` — the identical architecture with knots at per-feature quantiles and
one ridge solve — matches or beats the FIS-derived initialization *everywhere*
above one dimension:

| problem | quantile's margin over `hot` |
|---|---|
| Concrete | 22× faster to `1.25×` best; better final RMSE (4.739 vs 5.105) |
| bikeshare | 149× to FIS parity |
| damped pendulum | R² 0.9387 in 0.64 s and **zero updates** — better than any arm after 20 epochs |
| frictionless pendulum | 8× at every reachable target |

One asymmetry favours it and must be stated: its ridge solve fits the **labels**,
while the hot arms fit the FIS's output and never see `y` during setup. The fair
reading is that `quantile` is a *model*, not an initialization — and on these
problems it is usually the best model in the table.

**What TRIBBLE does contribute is feature selection.** On WEC, the same random
initialization trained on TRIBBLE's 12 columns reaches its target **9.2× faster**
than on all 301. Real, useful, and a different mechanism from the one under test.

## 6. Why: the additivity boundary

The cleanest experiment in the study is an A/B with one variable. Same FIS, same
conversion, same data generator; fluid damping present or absent:

| | FIS R² | seed R² | conversion loss |
|---|---|---|---|
| damped | 0.8746 | **0.8747** | none |
| frictionless | 0.6696 | 0.5562 | **0.11 R²** |

Damping makes the operator nearly additive in `t`. Removing it makes the
interaction between initial condition and time the entire problem — and the
axis-aligned conversion, which can only carry the FIS's additive part, loses
exactly that much.

This single boundary explains the whole study: why `quantile` keeps winning (an
additive knot basis is nearly the right hypothesis class whenever the conversion
is exact), why fidelity degrades with dimension (0.030 at one input, 0.294 at
eight, >1.0 at twelve), and why the tetrahedral construction was the right
instinct even though support limits it.

A caution on the frictionless case: it is not merely harder. Widening the network
8× moves its ceiling only from R² 0.725 to 0.771, and the FIS plateaus in the same
place. Two methods hitting one ceiling from opposite directions is an irreducible
component — without damping, trajectories separate exponentially and past some
horizon the operator is not a learnable function of a 0.1° grid of initial
conditions.

## 7. Defects

### 7a. In this module, found on review and since fixed

A later review (`outputs/nn-cmapss/REVIEW.md`) put this code on a dataset it was
not written against — N-CMAPSS DS02 — and turned up three of its own. All are
fixed here; `test_fis2nn.py` now runs 18 tests instead of 13.

1. **`triangle_to_relu` mishandled degenerate terms.** For `T(a=1, b=1, c=2)`
   it produced the *negation* of the correct falling ramp and kept falling past
   `c` — `max|err| = 1.0`, a full unit of membership, with no signal to the
   caller. The comment claiming "the falling side's expansion below reproduces
   it on its own" was simply false.

   The form that actually occurs here is milder and worth stating precisely,
   because the first attempt at this fix assumed it could not occur at all and
   broke the DS02 runs on contact. `fit_triangle_to_gaussian` returns a *fully*
   collapsed `a == b == c` when sigma is 0 — DS02 has one such feature,
   `Xs_T30_max`, 1 of 109 terms — and on that form the old code emitted no
   knots and an all-zero expansion. Wrong in kind, not in value: a collapsed
   feature entered the seed as silence, and every fidelity number here is
   unchanged by the fix. Zero-width terms now raise `DegenerateMembership`,
   `fis_knots` skips them and warns with a count, and inverted feet raise a
   plain `ValueError`. The trapezoidal analogues are covered too.
2. **`train_adam` charged evaluation time to training.** `hist.seconds` was
   `perf_counter() - start`, which includes every prior scoring pass over
   `X_test`/`X_val`. That cancels between arms of equal width and does not
   cancel otherwise — and §4's headline comparison puts a hot arm whose width is
   fixed by the FIS's knot count against an `he` arm free to be narrow (264
   against 8 on DS02). Eval time is now subtracted, so every reported second is
   a second of gradient descent. **Every wall-clock number in §4 predates this
   fix and is biased against the wider arm**, which on those runs is the hot
   one; the direction of the §4 conclusion is unaffected, but the ratios there
   should be regenerated before being quoted again.
3. **`analytic_seed_from_fis` is only sound for a 0th- or 1st-order TSK.**
   `partial_dependence` overwrites one column, which sends background rows off
   the joint data manifold; an affine consequent extrapolates gracefully there
   and a quadratic one does not. On DS02's `full-2nd` champion the seed lands
   31× the FIS's own standard deviation away from it, against 1.3× for the same
   pipeline at 1st order. Now documented, with the ALE-style fix named. §5's
   fidelity ladder (0.030 → 0.294 → >1.0) is unaffected — every FIS in it is
   1st-order.

The review also supplied the measurement §6 was missing: at each dimension, the
seed is compared not only to the FIS but to the FIS's own ANOVA projection on a
dense grid — *the best any axis-aligned seed of any width could achieve*. The
seed tracks that bound everywhere and sometimes beats it, which upgrades
"fidelity degrades with dimension" to **the conversion is optimal within its
class, and the residual is irreducible interaction**.

One caveat that belongs beside every fidelity number and was absent: past its
outermost knot the seed continues with the slope of the outermost segment,
forever. On DS02's `honest` pipeline 42% of test rows sit outside at least one
feature's knot range, and at one feature that extrapolation is essentially the
entire residual (0.070 against a best-additive 0.030).

### 7b. In the surrounding code, reported rather than patched

1. **`triangle_fit.fit_triangles_to_mixture` is unusable above ~6 features.**
   Compact support meets a product t-norm: one feature outside its triangles
   zeroes a rule, and the probability compounds with dimension. At 8 features on
   Concrete it predicts exactly zero for **71%** of rows; on bikeshare at 12,
   **100%**. Its docstring gives no warning. *Candidate upstream issue.*
2. **`_fuzzy_models.load_bikeshare` leaks its target.** `cnt` is exactly
   `casual + registered` and both are left in `X`. The first run here scored 0.897
   RMSE on a target with standard deviation ~181. Not patched, because proposal
   Tables 4.1 and 6.1 quote that loader — fixing it means re-running and
   re-quoting them, which is an author decision.
3. **A citation collision.** A web search for the "on the real line" title returns
   the 2023 conference and its outstanding-paper award, making the 2023 and 2024
   papers look like one. The 2025 paper's own bibliography settles it; all three
   are recorded separately in [`../../papers/nn-fis-equivalence/`](../../papers/nn-fis-equivalence/).

## 8. What this is good for, and what it is not

**Supported by the evidence.**
The equivalence is constructive and cheap in both directions, and gives a
*label-free* conversion that reliably lands at the FIS's own accuracy — 0.0035
error against a FIS's 0.0060 on PhiUSIIL, R² 0.8747 against 0.8746 on the damped
pendulum. As an explainability bridge, or a way to hand a fuzzy model to a
gradient-based toolchain without losing its accuracy, it works.

**Not supported.**
That FIS-derived knots are better ReLU knots. Five parts, four datasets, two
problem families, and a controlled A/B all say the placement is not the
contribution.

**Open.**
Every wall-clock number here comes from a NumPy trainer; absolute seconds are not
transferable to a GPU framework, though updates-to-target should be. And the
conversion has only ever been run against an *axis-aligned* first layer in
practice — the tetrahedral construction is exact and implemented, but support
limits confined it to low-dimensional subspaces. Whether a simplicial complex
built from TRIBBLE's own membership geometry, rather than an imposed lattice,
closes the additivity gap is the one substantive question this study leaves.

```bash
python experiments/fis-to-neural-net/test_fis2nn.py       # 13 exactness tests
python experiments/fis-to-neural-net/test_simplicial.py   # 12 tetrahedral tests
python experiments/fis-to-neural-net/run_experiment.py    # Parts 1 & 3 ladder
python experiments/fis-to-neural-net/run_simplicial.py    # Part 2
python experiments/fis-to-neural-net/run_warped.py        # Part 3 refinements

```

`git -C tribble-fis show …` that recovers it. Every artifact lands in
[`outputs/`](outputs/), which excludes derived CSVs.
