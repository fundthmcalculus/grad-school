# PLAN_FUZZYLOCAL: toward all-fuzzy blocks (registered 2026-10-19, before running; new direction from the user: "move away from convolutions and layer operations like that to proper fuzzy inference layers")

**What counts as a fuzzy inference layer here.** Fuzzification (membership functions on the inputs), a rule base (antecedents combined by a t-norm, consequents), aggregation and defuzzification. The model's two TSK components already are that: the feed-forward (Gaussian rules over a projected antecedent, first-order consequents) and the memory mixer (fuzzy partition of key/query space, delta-rule consequents). What is not fuzzy inference today, per block: (1) the causal depthwise convolution; (2) RMSNorm (before the mixer, before the FFN, and at the output); (3) the linear q/k/v and output projections of the mixer; (4) the linear antecedent projection and the slope of the FFN; (5) the sigmoid gates alpha (forgetting) and beta (write strength); (6) the tied embedding / output matrix.

**Stage 1 (this plan): replace the convolution with fuzzy local rules.** The convolution is a learned linear smoother over the last 8 tokens. The fuzzy counterpart already in the code is the multi-tap antecedent of the layer-0 FFN (`--ante-taps k`, `TapLinear`): a rule's antecedent is a conjunction over tokens t-k+1..t ("IF the previous token is A AND this one is B"), which is what a trigram rule needs and the convolution cannot express (it only blends).
Arms (BPE3072 tiered recipe, 30M characters, seeds 0-4; baseline = the recipe with the convolution, mean 1.0547, 98,528 params): `noconv` (97,760); `noconv_t3` (99,296); `noconv_t4` (FFN x1.45); `noconv_t8` (FFN x1.2); all at or under 99,999 parameters.
**Predictions.** Dropping the convolution without a replacement costs 0.005-0.030 BPC (70%). `noconv_t3` recovers at least half of that loss (45%) and matches or beats the convolution baseline (25%); more taps are better up to 4 (50%) and `noconv_t8` is worse than `noconv_t4` because the FFN had to shrink (60%). A fuzzy local rule layer replaces the convolution at no cost (within 0.003 of the baseline): 25%.
**Decision rule.** Paired over five seeds. A replacement within 0.003 BPC of the convolution baseline, or better, is adopted and Stage 2 starts; a loss of 0.003-0.010 is a price to weigh against "all-fuzzy"; more than 0.010 means the convolution is doing something the rule layer cannot (report what).

## Next stages (not run; for the owner to steer)
- **Stage 2, normalisation:** RMSNorm replaced by a fuzzy-partition normalisation (memberships summed to one) or removed; first test: remove each RMSNorm in turn (is it needed?), then the fuzzy alternative.
- **Stage 3, projections:** the mixer's linear q/k/v/out maps replaced by rule-based maps (a small TSK system per head), or the antecedent made to read the raw residual stream through per-dimension membership functions (fuzzification proper) instead of a learned linear projection.
- **Stage 4, gates:** alpha and beta as fuzzy systems of the input (the delta rule's forgetting and write strength as rule outputs).
Each stage is a 30M-character five-seed screen (about an hour), a 300M confirmation (12 minutes a seed) and a blind coherence set on the 300M checkpoints. **No 1B-character (or 3B) runs: the owner dropped them on 2026-10-19; the 300M cell is the largest budget from here on.** The deferred 3B-character tiered run and the 1B-character run of any new recipe are cancelled. ## Stage 3a registered before running (`FuzzyFFNRaw` in `flm/fuzzy_parts.py`, `flm/run_fuzzy_ffn.py`, `v47-fuzzyffn`): the FFN without its linear antecedent projection and without its linear slope
The FFN today is: a learned linear projection of the 48-dimensional input to a 16-dimensional antecedent, Gaussian rules over it (product t-norm), and a first-order consequent whose slope is another linear map. Proper fuzzification has no projection: each rule carries a membership function on each input dimension. Parameter-matched arms (about 10K parameters per FFN, 98.5K-99.2K in total), BPE3072 tiered recipe with the convolution kept, 30M characters, seeds 0-4, baseline mean 1.0547:
* **ffn_raw1**: 52 rules with Gaussian memberships on all 48 raw dimensions, first-order slope kept (98,488 at 2M-character smoke).
* **ffn_raw0**: 70 such rules, zero-order (no slope projection either) (98,576).
* **ffn_proj0**: the old projected antecedent kept, slope removed (zero-order), 120 rules (99,152): separates the cost of losing the slope from the cost of losing the projection.
Predictions: ffn_raw1 worse than the baseline by 0.005-0.030 (50%), within 0.005 (25%), better (10%), worse by more than 0.030 (15%); ffn_raw0 worse than ffn_raw1 (80%) and by >= 0.020 against the baseline (60%); ffn_proj0 worse by 0.003-0.020 (50%). The projection matters more than the slope (ffn_raw1 worse than ffn_proj0) (55%). Order of runs: stage 2/4 screen (running), stage 1 confirmation at 300M, then this; one GPU cell at a time.

## Stage 3b registered before running (`TSKMap`, `TSKLinear` in `flm/fuzzy_parts.py`, `flm/run_fuzzy_proj.py`, `v48-fuzzyproj`): the mixer's linear q/k/v and output projections as fuzzy systems
Per block the mixer has `qkv` (48 -> 144, 6,912 parameters) and `out` (48 -> 48, 2,304). Two parameter-matched replacements, both drop-in, BPE3072 tiered recipe with the convolution kept, 30M characters, seeds 0-4, baseline mean 1.0547:
* **proj_tsk0**: each map is a zero-order TSK system over the raw input (28 rules for qkv, 16 for out; Gaussian memberships on all 48 dimensions, product t-norm, normalised firings, consequent vectors, weighted-average defuzzification): a piecewise-constant interpolation between prototypes (98,144 params total).
* **proj_tskl**: each map is a first-order TSK system with a shared consequent basis, y = A (g * Bx) with g = sum_r w_r s_r (eight rules over the k = 32 (qkv) / 20 (out) basis coordinates): a fuzzy partition of locally linear maps; with s_r = 1 it is exactly the rank-k linear map and it starts there (checked, 6e-7) (98,720 params).
Predictions: proj_tsk0 much worse than the baseline: >= 0.05 BPC worse (75%), 0.01-0.05 worse (20%), within 0.01 (5%); proj_tskl worse by 0.005-0.03 (45%), within 0.005 (30%), better (10%), worse by more than 0.03 (15%) (the rank-32 bottleneck costs something even before the rules help). Order of runs after stage 3a; one GPU cell at a time; no run over 300M characters.
