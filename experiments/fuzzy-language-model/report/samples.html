What the fuzzy model writes at 1.2 bits per character

The fuzzy model now scores as well as neural models of its size, but it does not yet write coherent stories. Read the samples, then see why more post-training will not fix that and what might.

Verdict. Every model here writes real words in plausible sentences. None keeps a character, an object or a plot consistent for more than a sentence or two. The 280K neural teacher, which is 0.1 BPC better than the best fuzzy model, has the same flaw. Loss at this level buys fluency, not coherence.

Read the samples

Prompt text is in violet. Red words never appear in the training text (or appear fewer than 5 times). 400 characters, generated on CPU from the saved checkpoints with the full 256-character window.

What is wrong with the text

  • Spelling is solved. At temperature 0.7 with top-k 20, under 1% of generated words are non-words for every model.
  • Syntax slips and drift remain. Typical failures: "did not like it. One day, she found a toy with her friend, a long boy named Tim" (a new character from nowhere), "the dog watched the microscope as the park would make his bug", and names that swap mid-story.
  • Higher temperature trades coherence for variety. Temperature 1.0 triples the non-word rate and makes the grammar worse, so use the lower setting for any review.

Did post-training or size help?

Validation bits per character, first 1M characters of TinyStories V2 validation. 2 seeds for the 97K model. The only thing that helped is more training and more parameters.

  • Continuing training: +10M characters at a low learning rate gives −0.027 BPC. That is exactly what the pretraining curve predicts, so it is not a separate technique.
  • Weight averaging (EMA): −0.0005. No effect.
  • Distillation from the 280K teacher: no effect (+0.001). The teacher is better by 0.15 BPC but its soft labels carry little beyond the text itself at this scale.
  • Bigger models: 162K reaches 1.217 against 1.275 at 97K. Gains taper: the last +23K parameters bought −0.018.

Getting to coherent text

Coherence is about holding a story together across a few hundred characters: who is in it, what they own, what happens next. A character-level model spends most of its capacity on spelling and word boundaries. Here is what I would try, in order of expected value per hour of GPU.

  1. Give the model words, not letters. Train on a 512–1,024 token subword vocabulary and report bits per character so the number stays comparable. A story is about 4× fewer positions, so the same 256-token window sees a full story, and the recurrent state tracks characters instead of letters. The embedding costs 37–74K parameters at d = 72, so this needs the 160K size. ~2 h to build a tokenizer and run a 30M-character comparison
  2. Train much longer on the 160K model. 100M characters took the 97K model from 1.275 to 1.208. At 162K, 300M characters might approach the teacher's 1.115 (an extrapolation, not a measurement), and more data costs nothing. estimated ~1 h per 300M-character run if the GPU is otherwise idle
  3. Measure coherence, not just loss. Score samples for grammar, consistency and plot with a model-based grader, the way the TinyStories paper did, so the effect of each change is visible. Loss alone cannot show the gap above. ~30 min to build, needs an LLM API key
  4. Test the long-range memory directly. Check whether the fuzzy rule state remembers a character name 200 characters later with a copy task. Fix that before scaling if it fails. ~1 h
  5. Drop distillation and EMA. Both are measured null results.
