What a frozen dictionary costs

How many bits per character worse than a learned dictionary of the same shape, when the dictionary is built by hand and then never trained. Lower is better; each dot is one seed.

Where the loss falls

The hand-built 32-wide dictionary with letters as a 5-bit code, frozen against learned: bits per character added by each kind of next character (seed 0). Letters carry almost all of it, even though the model still picks the right letter about as often.

As a starting value instead

The same dictionaries used only as the initial values, then trained with everything else. Bits against the learned dictionary of the same shape.

How narrow can it go?

Learned dictionary, about 100,000 parameters at every width (rules per system rise as the width falls: the rule count is shown). Frozen with a flag per letter, 32 is the floor: 26 letter flags plus a 6-bit code to tell 47 non-letters apart.

The layouts

oh48 — 48 dimensions, every coordinate named
  • 0–25 letter flag, one per letter (shared by both cases)
  • 26–29 kind: digit, mark, whitespace, special
  • 30 unknown, 31 newline, 32 vowel, 33 digit value (linear)
  • 34–40 mark group: sentence end, pause, quote, open, close, joiner, arithmetic
  • 41–46 mark identity (6-bit), 47 upper case
squeeze32 — 32 dimensions, the floor
  • 0–25 letter flag (1.0 lower case, 0.6 upper case)
  • 26–31 a 6-bit code for the 47 non-letters (digits, space, newline, end of text, unknown, the marks grouped by punctuation group); zero for letters
