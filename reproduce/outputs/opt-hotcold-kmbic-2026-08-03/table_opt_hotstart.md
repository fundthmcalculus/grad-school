> Every arm optimizes the same k-fold held-out MSE inside the same box over the same 136 antecedent parameters, and is cut off at exactly 2000 objective evaluations by a wrapper that raises — no arm's own stopping rule is trusted to make the budgets equal. **The budget is evaluations, not time.** Wall-clock is kept per seed in the companion CSV but is not a variable this study controls, and every arm runs single-threaded, so parallelism is deliberately out of scope. `init=hot` starts from the Gaussian construction's own antecedents; `init=cold` from a uniform random point in the same box, everything else identical. Both are scored against the SAME reference — the heuristic model, R² 0.846 ± 0.025 — because a cold run's own start is a random point and improvement on it means nothing. `evals to reach heuristic` is how many evaluations a run needed before its objective matched what the construction supplies for free: the price of not having it, and the number this study exists to produce. Trust-region radius 1.0 (1.0 = the full box from `build_param_bounds`), centred on whichever point that run starts from.
>
> **`start-up cost` is not a pipeline comparison, and cannot be read as one.** Every init in this table needs the Gaussian construction first: it supplies the structure (which features, how many components per bucket) and the box that `build_param_bounds` derives. The k-means and FCM inits then *replace the placement* inside that structure, so their cost is construction + clustering and they are strictly more expensive than the construction alone. Showing k-means as a cheaper alternative would require the classical joint-space identification, where clustering chooses the rules instead of inheriting them — that changes the structure and belongs with `run_structure_study.py`.
