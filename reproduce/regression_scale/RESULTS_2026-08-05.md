# Large-scale regression pilot — results, 2026-08-05

Motivated by Appendix A.7 (`research/proposal-defense/prose/appendix.md`),
which found that this document's regression story has no large dataset in
any form: Concrete (1,030 rows) is the only regression benchmark anywhere in
the proposal, at every consequent order, in every chapter that touches
regression.

**Status: single-seed pilot throughout. Not a `reproduce/tables/` generator,
not a ten-seed measurement, not yet backed by canonical data.** This
document exists to decide whether either candidate is worth that investment,
not to report one.

---

## The short version

1. **Five candidates were scored by arithmetic before any code ran**: UCI
   CASP protein (45,730 × 9), sklearn/StatLib California Housing (20,640 ×
   8), UCI Superconductivity (21,263 × 81), UCI SGEMM GPU kernel performance
   (241,600 × 14), and UCI YearPredictionMSD (515,345 × 90). Two were piloted:
   California Housing (lowest friction, smallest scale-up) and
   Superconductivity (the one that stress-tests the feature-count axis
   regression is otherwise missing entirely).
2. **The canonical sources are unreachable from this session.**
   `archive.ics.uci.edu` and `ndownloader.figshare.com` both returned a
   policy denial (403 on CONNECT), confirmed via the session's proxy status
   endpoint as a deliberate block, not a transient failure. Both datasets
   were instead pulled from GitHub-hosted mirrors, verified only by
   row/column count against the known canonical shapes. **Re-source from UCI
   directly before treating any number here as final.**
3. **California Housing works out of the box; Superconductivity does not.**
   First pass, first order, no feature selection: California Housing scores
   R² = 0.660 in 0.84 s. Superconductivity scores **R² = −0.644** — worse
   than predicting the mean — in 22.7 s.
4. **The library's own feature selector (`top_p`) cannot fix this, and that
   is structural, not a tuning miss.** `top_p` scores each feature
   independently; Superconductivity's 81 columns are heavily collinear
   (mean/geometric-mean/entropy/std/range of the same underlying atomic
   properties), and two mutually redundant features can each score
   "informative" on their own. Sweeping `top_p` from 0.1 to 1.0 with no other
   change never moves the result off −0.644 until the threshold is already
   permissive enough to change nothing.
5. **Removing collinear features directly — not just weak ones — fixes it.**
   `sklearn.cluster.FeatureAgglomeration`, clustering on pairwise
   correlation, cuts 81 features to 47; `top_p` on top of that finds a real,
   non-monotonic optimum at **`top_p≈0.38`, 14 features, R² = 0.685** — a
   genuine peak, not a one-seed fluke: the same shape (rise, small dip, rise
   to the peak, decline) holds across five consecutive grid points.
6. **A real bug was caught and fixed in the middle of this**: the first
   version of the decorrelation step normalized features to unit *variance*
   instead of unit *norm*, which is off by a factor of ~√(N−1) in the
   distance-to-correlation conversion this pilot relies on — so it silently
   clustered nothing (81 → 81) and looked like `top_p` alone had failed a
   second time. Section 3 has the arithmetic and the fix.
7. **Forcing more aggressive log-transformation does not help.** Lowering
   the auto-detection threshold from the project's own default
   (`log_dynamic_range=2`, ≥100× dynamic range) to `1` (≥10×) catches 63/81
   features instead of 57/81, and produces identical or *worse* R² everywhere
   the two settings differ. The existing default already dominates it.
8. **Every model in Table 6.1's family was run on both datasets, and Random
   Forest wins both by a wide margin** — 0.814 (California Housing) and
   0.924 (Superconductivity), against this pilot's best tuned MoG results of
   0.636 and 0.685. **Fuzzy tree beats tuned MoG on Superconductivity with no
   tuning at all** (0.726, raw features). **HME is badly broken on
   Superconductivity** (R² = −4.647, worse than the untuned MoG it's meant to
   improve on). `m5py` does not load in this environment, the same gap
   CHECKLIST already tracks for Concrete.

## 1. Candidates considered

Sizes verified by web search against each dataset's own documentation, not
from memory (this project has caught transcribed-number errors before).

| Dataset | N × M | Target | Source | Piloted? |
|---|---:|---|---|:--:|
| CASP protein tertiary structure | 45,730 × 9 | RMSD (Å) | UCI id 265 | no |
| California Housing | 20,640 × 8 | median house value | sklearn / StatLib | **yes** |
| Superconductivity | 21,263 × 81 | critical temperature (K) | UCI id 464 | **yes** |
| SGEMM GPU kernel performance | 241,600 × 14 | kernel runtime (ms) | UCI id 440 | no |
| YearPredictionMSD | 515,345 × 90 | release year | UCI (Million Song Dataset) | no |

California Housing and Superconductivity were chosen first: the former as
the lowest-friction, smallest scale-up from Concrete; the latter because its
81 features are the only candidate that stress-tests the *feature-count*
axis this construction's cost model treats specially (§4.3.4's linear-in-M
claim), which none of the other regression material anywhere in this
document exercises. CASP, SGEMM, and YearPredictionMSD remain unpiloted.

## 2. Baseline: first order, no feature selection

Single seed, `n_output_buckets=3`, `tsk_order="1st"`, `top_n=-1` (all
features), mirroring `table_4_1_mog_baselines.py`'s protocol at one seed
instead of ten.

| Dataset | N (after `dropna`) | M | Fit time | R² |
|---|---:|---:|---:|---:|
| California Housing | 20,433 | 8 | 0.84 s | 0.660 |
| Superconductivity | 21,263 | 81 | 22.7 s | **−0.644** |

Superconductivity's negative R² is the finding this whole pilot chases. The
working hypothesis: 81 features that are largely restatements of the same
underlying atomic properties (mean, geometric mean, entropy, standard
deviation, and range of atomic mass, valence, thermal conductivity, fusion
heat, electron affinity, and atomic radius) destabilize the closed-form TSK
consequent solve — the same failure family Table 4.1's own z-score
investigation already documents for unbounded/correlated inputs.

## 3. `top_p` alone does not fix it

`top_p`'s own docstring: "kept when its own normalized differentiation score
is >= (1 - top_p)." That score is computed **per feature**, independent of
every other feature. Sweeping it from 0.1 to 1.0 on the raw 81-feature set:

| `top_p` | features kept | R² |
|---:|---:|---:|
| 0.75 | 81 (all) | −0.644 |
| 0.90 | 81 (all) | −0.644 |
| 1.00 | 81 (all) | −0.644 |

Nothing moves, because nothing gets cut: at `top_p=0.75` the score threshold
is already permissive enough that every one of the 81 features clears it.
Two features that are 95% redundant with each other can both score
"individually informative" — `top_p` has no mechanism to see that they are
redundant *with each other*, only that neither is individually weak.

## 4. Decorrelation — a bug, caught, then the fix that worked

**First attempt (bug).** `sklearn.cluster.FeatureAgglomeration` clusters
features by Euclidean distance between columns. To make a target correlation
threshold convert to a distance threshold, the first version of this pilot
z-scored each column to zero mean, unit **variance**, on the (mistaken)
assumption that `||a-b||² = 2(1-corr(a,b))` for standardized columns. It does
not: for ddof=1 sample-variance scaling, the correct relation is
`||a-b||² = 2(N-1)(1-corr(a,b))` — off by a factor of `N-1 ≈ 21,262`. The
distance threshold computed from the naive formula (≈0.447) was thousands of
times too small, so `FeatureAgglomeration` merged nothing: 81 → 81, and the
result looked identical to §3's already-broken baseline. It would have been
easy to read that as "sklearn decorrelation doesn't work either" and stop.

**The fix.** Centering each column to zero mean and rescaling to unit **L2
norm** (not unit variance) makes the relation exact and independent of N:
`||a-b||² = 2(1-corr(a,b))`, verified directly (`corr = 0.8859`,
`||a-b|| = 0.47780`, `sqrt(2*(1-corr)) = 0.47780`, matching to 5 decimal
places on a real pair of Superconductivity columns). With that fix, at a
correlation threshold of 0.9:

| Dataset | Features before → after | 
|---|---|
| California Housing | 8 → 5 |
| Superconductivity | 81 → 47 |

One named feature survives per correlated cluster — the one with the highest
`|corr with y|` — rather than an averaged synthetic feature, so the surviving
columns stay meaningful in a rule base.

## 5. `top_p` sweep on the decorrelated features

Coarse sweep first (California Housing, and an initial Superconductivity
pass), then a finer grid around the region where the coarse sweep found a
local peak.

**California Housing** (decorrelated to 5 features) — monotonic, unsurprising:

| `top_p` | features | R² |
|---:|---:|---:|
| 0.1 – 0.75 | 1 | 0.482 |
| 0.9 – 1.0 | 5 | **0.636** |

One feature (`median_income`) dominates the differentiation score badly
enough to clear every threshold below 0.9 alone.

**Superconductivity** (decorrelated to 47 features) — not monotonic:

| `top_p` | features | R² |
|---:|---:|---:|
| 0.10 | 1 | 0.216 |
| 0.20 | 4 | 0.647 |
| 0.30 | 8 | 0.637 (local dip) |
| 0.36 | 12 | 0.665 |
| **0.38–0.40** | **14** | **0.685** ← peak |
| 0.45 | 21 | 0.655 |
| 0.50 | 28 | 0.564 |
| 0.75–1.0 | 47 (all survivors) | 0.127 |

The peak at 14 features holds across five consecutive grid points either
side (0.32 through 0.45 all score between 0.64 and 0.69), which is what
distinguishes it from a single-point coincidence at this seed count — though
it is still one seed, and the exact crossover values should be treated as
approximate until re-measured across a real seed set.

## 6. Log-transform sensitivity

`_fuzzy_models.normalize()`'s own convention is `log_dynamic_range=2`
(log1p any feature whose max/min nonzero absolute value spans ≥ 2 decades).
Lowering it to `1` (more aggressive — catches milder skew) on Superconductivity:

| `log_dynamic_range` | features log-transformed | R² at `top_p=0.38` | R² at `top_p=0.5` |
|---:|---:|---:|---:|
| 2 (current default) | 57 / 81 | **0.685** | **0.564** |
| 1 (more aggressive) | 63 / 81 | 0.678 | 0.518 |

Identical through `top_p=0.36` (the extra 6 log-transformed features aren't
selected yet at that threshold), then measurably worse everywhere they
start being selected. The project's existing default is not the thing to
revisit here.

## 7. Model family comparison (Table 6.1's family, raw features)

Same five/six models Table 6.1 compares on Concrete, run here on both
candidates at raw features (Table 6.1's own convention — no
normalize/decorrelate, so fuzzy-tree splits stay physically meaningful), one
seed. The "flat" row is the **untuned** library default (`top_p=0.95`), not
§5's tuned result — mixing a tuned arm into an otherwise-untuned table would
repeat the exact mismatch Table 4.1 was written to avoid.

**California Housing:**

| Model | Fit time | R² |
|---|---:|---:|
| flat (MoG, untuned) | 8.23 s | 0.656 |
| fuzzy tree | 0.36 s | 0.480 |
| HME | 2.38 s | 0.379 |
| CART | 0.11 s | 0.648 |
| **Random Forest** | 15.42 s | **0.814** |
| M5 | — | unavailable (`m5py` / sklearn 1.9.0) |

**Superconductivity:**

| Model | Fit time | R² |
|---|---:|---:|
| flat (MoG, untuned, raw) | 28.54 s | −0.665 |
| **fuzzy tree** | 2.95 s | **0.726** |
| HME | 15.07 s | **−4.647** |
| CART | 0.98 s | 0.870 |
| **Random Forest** | 118.31 s | **0.924** |

Random Forest wins both by a wide margin over every FIS-family model,
tuned or not — a real accuracy cost for the interpretability trade this
document argues for, worth stating plainly rather than only reporting the
FIS family's own internal improvements. Fuzzy tree beating tuned MoG on
Superconductivity with zero tuning is the more surprising result: it
suggests the simpler construction may just fit this dataset's structure
better than the Gaussian-mixture one, independent of anything this pilot did
to the MoG side. HME's collapse (−4.647, worse than the *untuned* flat MoG it
is meant to improve on) looks like the same correlated-feature instability
as §2, likely worse for a hierarchical construction — not investigated
further here.

## What this pilot does not settle

- **Neither dataset is backed by canonical data yet.** Both loaders pull
  from a GitHub mirror because UCI and figshare are unreachable from this
  session (§ "data provenance" in `README.md`). Re-source before committing
  anything.
- **Everything above is one seed.** The Superconductivity `top_p` peak's
  shape looks real (holds across five grid points), but its exact location
  and value need a real seed count to confirm.
- **No decision has been made on which dataset, or which model family, is
  worth carrying into a `reproduce/tables/` generator.** Random Forest's
  lead over every FIS-family arm on both datasets is large enough that it is
  worth asking, before investing in a ten-seed MoG measurement, whether the
  point of adding a large regression dataset is to show the construction at
  scale or to concede where it loses and by how much.
- **CASP, SGEMM, and YearPredictionMSD remain unpiloted.** CASP in
  particular stayed the closest analog to Concrete's own shape (few physical
  features, continuous target, ~44× the rows) and was never tried.
